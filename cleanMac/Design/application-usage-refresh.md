# 应用占用列表刷新

1. 每次采样重新读取运行应用，包含普通窗口应用和独立菜单栏应用；嵌套辅助应用继续归属主应用，系统后台代理不单独列出。
2. 优先使用内核进程启动时间建立运行实例身份，兼容 NSRunningApplication 未提供 launchDate 的应用；结束应用仍重新核对进程身份、所属用户与保护策略。
3. 监听应用启动、退出和激活通知，主动更新列表；采样中的刷新请求合并为一次后续采样，避免丢失请求。仍保留每 5 秒的定时采样。
4. 新应用首次出现时先显示内存，CPU 在取得两个有效采样后显示，不把未知用量显示为零。
5. 应用包与进程可执行文件使用相同的路径规范化，避免 `/private/tmp`、`/tmp` 等路径别名导致进程关联失败。
6. 应用行右键菜单提供“正常退出应用”和“强制结束进程…”，强制结束需确认。系统、受保护应用及 cleanMac 自身禁用结束操作；执行时重新校验进程身份，结果在列表底部显示并可关闭。
7. 应用行悬停时渐显玻璃背景，按下时降低透明度；保持行尺寸与文字位置稳定，并遵循系统“减少动态效果”设置。
8. 为运行实例注册进程退出事件，确认退出后立即移除应用、异常提醒与趋势；后台采样提交前再次核对内核进程状态及启动时间，避免旧采样把已退出实例加回。正常退出被取消时继续保留应用。

验证：arm64 Debug 构建通过，150 项核心与文件系统回归测试通过。使用临时普通应用和菜单栏应用验证启动后出现、刷新请求合并、内存可读取及退出后移除，并核对系统未提供 launchDate 的现有应用仍能列出。未结束用户的实际应用。

右键菜单验证：使用临时测试应用核对强制结束确认、取消、正常退出后的列表移除和操作反馈；cleanMac 的结束操作正确显示为禁用。未结束用户的实际应用。

退出刷新回归：153 项回归测试及 arm64 Debug 构建通过。临时普通应用正常退出、菜单栏应用强制结束、应用取消正常退出后再强制结束均通过实测。将进程采样结果延迟 2 秒返回，确认退出行在旧采样返回前移除，且旧结果不会恢复应用、趋势或提醒；用相同场景运行修复前的监控逻辑会复现延迟移除失败。
