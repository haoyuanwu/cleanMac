# 应用与开发：存储盘点

1. 包管理器：扫描 Homebrew、npm、pnpm、Yarn、pip、Cargo、Gradle、CocoaPods，并补充 Maven、uv、SwiftPM 的常见缓存位置。不扫描包管理器凭据、Cargo bin 等已安装程序。
2. AI / 工具链：扫描 Ollama、Hugging Face、nvm、rustup、pyenv、Claude Code、Codex、Cursor、VS Code。模型、工具链、会话和扩展本体仅查看，使用所属软件管理。AI 页面按软件分组，可展开缓存、日志与临时目录并勾选清理。Ollama 和 Hugging Face 支持当前应用进程继承的 OLLAMA_MODELS、HF_HOME、HF_HUB_CACHE 绝对路径。
3. 容器与虚拟机：统计 Docker、Parallels、UTM、VMware、OrbStack、Lima、Colima 默认数据位置。Docker CLI 使用本机 socket 运行只读 system df，8 秒超时；不会启动引擎、连接远端 context 或执行 prune。引擎可回收估算与虚拟磁盘占用分开显示，不相加。
4. 工程产物：递归 Desktop、Documents、Projects、Developer、Code、repos，依据同级项目标识识别 node_modules、.next、.nuxt、.build、build、dist、Pods、target。跳过链接、隐藏源码目录、应用包和已识别的产物子树；普通同名目录不会被当作工程产物。

以上均为按需扫描，不纳入一键清理或系统数据汇总。非默认存储路径可能未覆盖。使用元数据测量逻辑大小和文件系统分配大小；硬链接、克隆、稀疏磁盘导致这些数值不能直接当作最终释放量。缺失目录忽略，读取失败和取消会标明结果不完整。

包管理器缓存、AI 工具缓存和工程产物默认不选中，用户确认后移到废纸篓；清空废纸篓后才会释放空间。操作前重新核对路径、符号链接、项目标识和白名单；含白名单子项的目录不允许整目录清理。工程目录仍需用户确认未存放手写文件，停止构建并保留恢复依赖的来源。

实现依据：[Docker system df](https://docs.docker.com/reference/cli/docker/system/df/)、[Hugging Face 缓存](https://huggingface.co/docs/huggingface_hub/guides/manage-cache)、[Ollama FAQ](https://github.com/ollama/ollama/blob/main/docs/faq.mdx)。

## 界面与交互

- 四页共用与 Xcode 页面一致的 920pt 内容宽度、28pt 水平留白、圆角图标、玻璃卡片和扫描矢量动画。扫描居中展示真实当前路径、检查次数和耗时；支持取消，切换页面后继续扫描。取消重新扫描会保留上次完整结果。
- 逻辑总量突出展示，行内区分逻辑大小与磁盘分配大小。支持工具筛选、搜索、排序和展开完整路径及影响说明。只读项保持正常文字对比度，不作为禁用按钮显示。
- 可选行的主体区域均可点击，详情展开独立触发。批量选择仅包含当前筛选结果中允许处理的目录；筛选收窄会丢弃隐藏项的选择，清除筛选不会恢复它们。切换模块或重新扫描清空选择。
- 确认面板固定本次目录快照，逐项列出路径、数量和大小；明确处理目录及全部内容。执行前重新检查路径与白名单，操作结果归属原模块，失败信息可展开查看。未执行真实用户文件的清理验证。

验证：169 项文件系统和核心逻辑回归测试通过；arm64 Debug 构建通过。实际窗口检查了初始态、扫描动画、结果列表、批量选择、筛选收缩范围及确认面板。浅色 / 深色小字号文本分别使用 RGB (0.24, 0.27, 0.33) / (0.84, 0.87, 0.93)。按共享背景的三个基色、径向叠色 0 / 0.5 / 1 强度及行表面混合采样，最小文字对比度分别为 4.78:1 / 4.62:1，选中边框分别为 4.46:1 / 3.40:1；这是颜色令牌采样，不是系统材质像素级或深色实机截图验证。


## AI 软件缓存明细

AI 软件总目录仅盘点；在 `.codex`、`.claude`、`.cursor`、`.vscode`、`.ollama`、`.nvm`、`.rustup`、`.pyenv` 及已知编辑器数据位置，识别 `tmp` / `temp` / `cache` / `caches` / `.cache` / `log` / `logs` 等目录（含 Chromium Code Cache、GPUCache 等）。只递归固定包装层，不进入 sessions、projects、plugins、extensions、models、toolchains、versions、workspaceStorage 等目录搜寻同名缓存。Claude Code 的 debug、rustup 的 downloads、Hugging Face 的 xet 也作为对应工具的临时/下载数据列出。

软件总占用包含下方缓存，不叠加计数。展开软件后可逐目录勾选或选择该软件当前结果中的全部缓存；收起软件会取消该组的选择，搜索按缓存子路径匹配。根目录始终只读。清理后移除成功的缓存子项并扣减父目录的已扫描占用，失败项保留；实际占用变化仍以重新扫描为准。白名单、符号链接和固定路径层级在扫描及执行前均检查。

## 右键菜单

四个模块共用目录菜单：Finder 定位、复制路径、展开/收起详情。允许清理的目录另提供选择/取消选择和“移到废纸篓…”；该项仅审查右键点击的目录，仍需确认。当右键目录已选中且存在多选时，另显示明确带数量的“检查所选 N 项…”。右键本身不改变选择，确认单目录操作只扣除本次处理目录的选择，保留其他已选项。

AI 软件分组菜单支持展开/收起、定位/复制当前结果中的软件数据目录、选择该软件当前结果中的缓存、取消其缓存选择。选择缓存会自动展开分组。模型、虚拟机及其他只读目录没有清理菜单；Docker 引擎报告支持复制与重新扫描，不提供 prune 操作。任务处理中禁用选择和清理，定位与复制仍可使用。

本次右键菜单改动通过 arm64 Debug 构建及目录菜单显示检查；未执行真实目录清理。

## 扫描状态统一

所有共享扫描占位页及概览使用 ScanProgressFeedback，统一展示当前路径、已用秒数、实际检查次数。任务持有诊断收集器，页面内周期刷新；切页再返回沿用任务开始时间。分类扫描沿用已有诊断快照，四个开发模块移除重复的自行统计排版，Xcode、重复文件、磁盘目录和只读检查接入各自真实读取进度。概览保持原进度条与动画，同时补齐本阶段路径和检查次数、整次扫描耗时。未知计数显示“等待统计”。

验证：175 项回归测试、arm64 Debug 构建通过；实际 Xcode 页面观察到当前目录、17 秒用时及 381740 次检查的实时反馈。

## 扫描结果空间分配

四个开发模块的结果态改用紧凑页头：原独立汇总卡合并到标题区，保留逻辑占用、工具数及可选目录数；筛选区纵向间距缩小，底部操作栏改为单行，范围说明保留在信息图标提示及辅助功能标签中。读取问题与操作消息移入列表滚动区，避免持续挤占列表视口。目录行字号和点击区域保持原样，初始态及扫描态沿用原布局。
