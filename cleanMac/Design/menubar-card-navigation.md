# 菜单栏速览卡片导航

复用原有卡片、图标和 WorkspacePressStyle：实时内存打开“内存状态”；实时网速、Wi-Fi 和蓝牙打开“网络与连接”；空间与电池分别打开“存储空间”“电池与电源”。废纸篓的数据区打开废纸篓详情，清空按钮维持独立操作，避免嵌套按钮导致误触。

AppActionCoordinator 使用可消费一次的目标页请求；先记录目标再关闭弹窗并激活主窗口。窗口关闭时请求保留至主视图创建，在启动后台快照之前处理；已有窗口沿用激活和取消最小化逻辑。连续点击以最新目标为准，清除旧的设备概览与废纸篓跳转请求。

验证：183 项回归测试及 arm64 Debug 构建通过，新增全部目标页请求保留/消费一次及最新目标替换过期导航的测试。自动 UI 检查可打开主窗口，但系统状态栏界面读取超时，未完成真实状态栏卡片点击与落地页的端到端验证。

## CPU 卡片与内存整理

状态栏新增实时 CPU 卡片，复用 DeviceTelemetryMonitor 和支持紧凑模式的 TelemetryChart，展示整机归一化使用率、用户/系统占比与最近一分钟趋势，每两秒采样。只在卡片可见时保留采样客户端；点击使用同一导航请求进入 CPU 详情。图标沿用 CPU 页面使用的系统 cpu 图标。

内存状态页和状态栏共享 MemoryMaintenanceButton 与 MemoryMaintenanceService。状态栏按钮先打开内存详情，再使用已有 ModalDialogView 显示确认，防止授权弹窗导致瞬态状态栏关闭后反馈丢失。整理按钮位于导航按钮之外，不嵌套按钮。执行前说明需要管理员授权，使用 macOS /usr/sbin/purge 整理磁盘缓存，不退出应用、不释放 malloc/vm_allocate 等应用匿名内存；可能短暂影响性能，内存占用不保证下降。依据本机 purge(8) 手册。操作完成提供前后已用内存估算或失败/取消/超时原因，共享运行状态阻止重复执行。

验证：185 项回归测试、arm64 Debug 构建通过，包含 CPU 请求消费以及模拟整理完成、取消、运行防重入测试；实际内存详情页面验证按钮、确认文案与取消。未执行真实 purge 或管理员授权；状态栏实机点击验证仍受 UI 自动化访问限制。

## 紧凑布局修订

常用的扫描/深度清理操作紧跟标题，存储与废纸篓放在前面；CPU 与内存并排显示摘要，趋势保留在详情页。网速使用横排上下行数值；电池、Wi-Fi 并排，蓝牙在其后。移除电池、蓝牙、Wi-Fi 和废纸篓的固定高卡片，让内容决定高度，退出操作留在底部。弹窗宽 350 点、高 570 点，由同一个尺寸定义同步到 NSPopover，避免容器裁切。内存整理是独立按钮，保持原确认与管理员授权流程；废纸篓清空按钮仍是独立操作。

导航图标保留模块色，操作按钮使用紫色浅底与深色标签，危险操作保持红色。未添加依赖，未生成安装包。通过 Xcode 官方 MCP 构建与运行验证，测试后停止实例。


## 直接整理与蓝牙列表

整理内存按钮直接调用共享服务，不再显示应用内确认，也不再从状态栏强制跳转主窗口。服务仍处理管理员授权、执行互斥、超时和结果反馈；系统授权仍由 macOS 提供。模拟测试验证直接启动、运行中重复点击只调用一次，以及取消授权结果，不执行真实 purge。

蓝牙卡片标题和连接数量放在同一行，下方完整列出设备。设备名称与卡片左边缘对齐，右侧固定电量列显示电池图标与百分比；充电时复用 ChargingBatteryBadge 的紧凑样式，显示闪电电池和百分比。未知电量显示问号与 —%，低电量保留颜色和无障碍说明；不再因充电设备覆盖其他设备。

本次验证：Xcode MCP 编译通过，185 项回归测试通过（包含直接启动且重复请求仅调用一次的模拟测试）。专用蓝牙样例预览覆盖正常、充电、低电量及未知电量；RenderPreview 返回 TaskTimeoutError，未完成截图复核。未执行真实内存整理或管理员授权；已关闭测试实例。

## 卡片内整理与标题栏退出

整理按钮移入内存卡片底部：数据区是详情导航按钮，整理是同一卡片中的独立按钮，避免嵌套按钮；完成反馈在紧凑结果气泡显示，不因长文案撑高卡片。退出移动到标题栏右侧的电源图标，保留明确的退出提示和无障碍名称，底部仅显示更新时间。

状态栏各卡片共用 popupCard：14 点圆角、GradientGlassSurface、固定轻阴影与统一内边距。内存/CPU 以 embedded 模式复用数据组件，避免双重背景；存储、废纸篓、网速、电池、Wi-Fi 和蓝牙使用同一表面。正常按钮保留自己的功能色。Xcode MCP 编译通过，未执行真实整理、退出操作或打包。本轮未完成状态栏截图复核。
